## 3. Four defects found in the project's own verification apparatus

These matter more than the line count, because each one was something that
looked fine.

1. **`reproduce.sh` reported PASS for failing steps.** It used
   `if cmd | tee log; then` with no `pipefail`, so the status read was `tee`'s —
   always 0. Confirmed directly: `if false | tee /dev/null; then echo PASS; fi`
   prints `PASS`. Unrelated to K-16; it would have masked any future regression.
2. **`data/hashes/SHA256SUMS.lean` was stale and partly unenforced** — 4 of 8
   entries FAILED, and 3 Lean sources were covered by no hash at all. Found only
   by the first genuine **fresh-clone** run; in-place checking cannot see this.
   `scripts/` was also untracked, so a fresh clone had no verification
   entrypoint.
3. **Three validators exited 0 on inputs that establish nothing** (K-19): an
   empty `cases` list, a self-consistent lower-bound file reporting `I = 0`, and
   a DRAT proof deriving no empty clause. Two are now fixed at source;
   `dratcheck.py` is not, and the harness gate is what catches it.
4. **An earlier prose result had wrong numbers.** The unrecoverable 25-case run
   claimed `none` SAT in 9; the shipped run says 13. The shipped figure is right
   — 1 + 8 + 4 reconciles exactly with that paragraph's *own* orbit claim, so 9
   was a miscount. Its "four orbits" was also wrong (three, among the
   both-adjacent types). Corrected in `docs/a7-specification.md` §9.7.
